## Incremental compilation foundations

This candidate packages four verified development milestones added after
v0.0.6-alpha.1. These are **opt-in Rust embedding APIs**, not new Scarp source
syntax, executable CLI modes or a complete incremental compiler.

1. **Conservative module invalidation planning** — capture dependency-aware
   graph snapshots and plan affected sources without resolving the whole graph
   by guesswork. Compare post-recompile imports, source identities, labels and
   alias targets before treating unchanged metadata as valid.
   [Design contract](../development/incremental-invalidation.md),
   [PR #121](https://github.com/scarp-lang/scarp/pull/121).
2. **Whole-graph semantic resolution cache** — a caller-owned,
   bounded FIFO of successful linked/type/constant results. Every request
   loads the current graph, checks exact source bytes, compiler limits,
   import targets, diagnostic display labels, source identities and
   caller-owned document revisions before reusing a prior semantic success.
   Compiler failures cannot be masked by older successful outputs.
   [Contract](../development/semantic-cache.md),
   [PR #122](https://github.com/scarp-lang/scarp/pull/122).
3. **Per-file source-relative lexer tokens** — reuse tokens only for an exactly
   matching loader identity and UTF-8 source; shift byte spans to the current
   source-map base. The standard importer and parser still validate current
   input and resource budgets. Separate FIFO and logical source/token/identity
   quotas prevent unbounded *retained logical payloads*.
   [Contract](../development/token-cache.md),
   [PR #123](https://github.com/scarp-lang/scarp/pull/123).
4. **Per-file parsed syntax tree reuse** — cache successful ASTs with
   source-relative spans, cloning and rebasing all nested statement, function,
   contract, labeled-argument, annotation, import and expression locations
   before linking. Lex/parse failures are never stored, and current import,
   depth, cycle, visibility, type, constant and resource checks still apply.
   The syntax, token and semantic caches can be combined without global state.
   [Contract](../development/syntax-cache.md),
   [PR #124](https://github.com/scarp-lang/scarp/pull/124).

### Rust embedding example

```rust
use scarp::modules::{
    self, MemorySourceLoader, ModuleLimits,
    cache::{SyntaxCache, SyntaxCacheLimits},
};
let mut files = MemorySourceLoader::new();
files.insert("main.srp", "import \"lib.srp\" as lib; print(lib.value);")?;
files.insert("lib.srp", "pub bind value=42;")?;

let mut cache = SyntaxCache::new(SyntaxCacheLimits::default());
let one = modules::resolve(modules::load_with_syntax_cache(
    "main.srp", &files, ModuleLimits::default(), &mut cache
)?)?;
let two = modules::resolve(modules::load_with_syntax_cache(
    "main.srp", &files, ModuleLimits::default(), &mut cache
)?)?;
assert_eq!(one.sources().files().len(), two.sources().files().len());
assert_eq!(cache.stats().hits, 2);
# Ok::<(), Box<dyn std::error::Error>>(())
```

The compiler library remains available through **Cargo-built source**. Native
GitHub archives contain the Scarp CLI plus examples and documentation; they
do **not** package a separate precompiled Rust library, a native Scarp compiler
executable generator, or a language server.

## Correctness and performance validation

- Regression coverage of Unicode/CRLF source-length edits, source-order and
  SourceId changes, syntax/lexer errors, private imports, missing files, alias
  retargets, module budgets, revision changes, deterministic cache eviction,
  and cold-versus-cached symbol/reference JSON and execution parity.
- The compiler benchmark includes cold and warmed four-file module workloads
  for lexical tokens, syntax trees and the combined caches. Each sample
  checks source/compiled shape and reuses the same benchmark input. Raw
  timings are **host-specific observations**, not a speed guarantee.
- Alpha.2 release verification additionally requires the four cache design
  documents in each native archive and rejects missing/tampered files or
  stale release metadata even when archive checksums match.

For a checkout with a compatible Rust toolchain, run:

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked --release
cargo bench --locked --bench compiler -- --quick
python3 -m unittest scripts/test_release_assets.py scripts/test_release_docs.py
```

The automated project scripts additionally exercise examples, native
packaging, minimum Rust 1.74 and platform-specific C differential checks.
A GitHub Release must be verified against its **exact tagged source commit**.

## Compatibility and explicit deferrals

Scarp remains an **experimental interpreter-backed language**. The published
alpha.1 Scarp-first CLI, bounded source navigation, finite RMS, module
resolution, project commands and experimental Rust-hosted scalar C11 emitter
remain available. Candidate cache APIs are additive and opt-in; standard
cold compilation does not install or mutate global caches. Caching does not
change valid program outputs or error codes.

This release **does not** add general immutable fixed-size arrays, richer type
expressions, GPU execution, an LSP server, file watchers, durable compiler
caches, per-module semantic linker reuse, general native executable compilation,
or a package registry. The existing C11 emitter still supports only its
documented restricted scalar subset. Syntax and Rust APIs may evolve before
a stable release.

The caches have **logical retention budgets**; they do **not** report or
guarantee total heap consumption, and a cache hit still incurs loader work.
Compiler benchmarks should report measured values rather than asserting
performance improvements across hardware or workloads.

## Platform and publication gates

The proposed archive targets remain Windows x64 MSVC, Linux x64 GNU, and
macOS Apple Silicon. An eligible prerelease must pass all four Rust jobs
(Ubuntu, Windows, macOS, minimum Rust 1.74) and three native-package jobs
on the exact approved source **and** on the subsequent authorization control
revision. Each archive must carry a matching
`RELEASE-METADATA.json` with `version = 0.0.6-alpha.2`, source-matched
examples/docs, and clean `BUILD-INFO.txt`. The publisher checks each
archive, individual SHA-256 sidecar and `SHA256SUMS`, then validates draft
and public download bytes.

A future publication record must provide exact SHA-256 values generated
from published assets. Do **not** reuse alpha.1 checksums or claim that
a PR run or candidate version string proves a public release.
