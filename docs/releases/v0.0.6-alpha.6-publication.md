# Scarp v0.0.6-alpha.6 — prerelease

Scarp adds a connected set of core language foundations: bounded program input,
explicit scalar/text conversion, and immutable heterogeneous tuples.

## New in v0.0.6-alpha.6

- `read_line() -> string` reads an explicitly supplied UTF-8 line. Rust hosts
  inject a buffered reader; `exec`, `run` and `launch` accept redirected stdin.
  EOF, invalid encoding, reader errors and quota failures have distinct diagnostics.
- `integer_to_text`, `float_to_text`, `text_to_integer`, `text_to_float`,
  `text_trim` and `text_replace` provide checked explicit conversions and bounded
  Unicode text utilities. Integer parsing checks the signed i64 range; finite
  float parsing remains explicit and does not add implicit string conversion.
- Tuples support heterogeneous values such as `(42, "नमस्ते")`, singletons
  `(42,)`, structural `tuple<integer, string>` annotations and literal projection
  `value[0]`. They work across functions, defaults, contracts, recursion and
  public/private imported function interfaces. Whole-value replacement requires
  the exact same type. Equality is structural; nested strings are escaped.
- Compiler-owned conformance programs, integration regressions and packaged
  examples cover these features together. `examples/core_input_tuple.srp` reads
  CRLF input, parses a number, transforms Unicode text and exchanges an imported
  tuple. The extracted native executables run exact-byte stdin/stdout fixtures.

## Compatibility and limits

Scarp remains experimental. Rust embedders must migrate source-facing type fields
and `Value::kind()` to structural `SourceType`, handle `Value::Tuple`, and add
`max_tuple_bytes` to complete `ExecutionOptions` literals. Primitive type IDs are
unchanged. Module inventories exposing tuple signatures use schema 2;
primitive-only inventories and symbol/reference/diagnostic JSON remain schema 1.

Tuple arity is 1–32, nesting at most 32, structural shape at most 4096 nodes and
the default cumulative tuple payload quota is 8 MiB. `--max-tuple-bytes` changes
that logical cap. Input defaults are 65536 raw bytes per line, 1048576 total bytes
and 4096 reads, adjustable through the three `--max-input-*` flags or `InputLimits`.
Existing execution, text, numerical and output budgets still apply.

LF/CRLF terminators are removed from returned text but count toward quotas.
Input consumption cannot be rolled back; captured program output is replayed
only after successful evaluation. Terminal-connected input and historical
evaluating `check` report E0054 at a selected read. `verify` and inspection remain
static. This release does not provide an interactive prompt API.

Empty tuples, tuple constants, computed/dynamic tuple indices, destructuring,
element mutation, BigInt, general arrays/maps and optional/result values remain
outside this release. Native backends explicitly reject input and tuples. Existing
scientific/AI kernels and the experimental narrow C11/ELF64 APIs remain available;
there is no general native executable CLI, GPU runtime or stable ABI.

## Downloads and compiler contracts

The release provides Windows x64 MSVC, Linux x64 GNU and macOS Apple Silicon
archives, one SHA-256 file per archive and a combined `SHA256SUMS` manifest.
Each archive records its clean source commit in `BUILD-INFO.txt`.
