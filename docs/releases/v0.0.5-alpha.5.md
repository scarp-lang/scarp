# Scarp v0.0.5-alpha.5 — prerelease candidate (not published)

**Status:** development candidate only. This document does not authorize tagging,
publishing or treating alpha.5 as a publicly available release. The latest
published prerelease remains v0.0.5-alpha.4 until the exact-source publication
and downloaded-asset verification gates complete.

Scarp remains an experimental, Rust-based programming language. The executable
distributed in native archives is the Scarp interpreter/compiler CLI; it is
**not** a self-hosting native compiler for general `.srp` programs.

## Changes since published alpha.4

- **Project module inspection:** `scarp inspect modules --json DIRECTORY` and
  the compatible `scarp modules --json DIRECTORY` resolve an explicit
  `Scarp.project` safely and emit existing schema-v1, read-only module metadata.
  Invalid manifests, traversal and symlink escapes are rejected using the same
  source-root policy as `verify DIRECTORY`.
- **Experimental scalar C11 code generation (embedding API):**
  `scarp::c_backend::emit_c` / `emit_program` produce a complete
  freestanding C11 translation unit for a deliberately restricted subset,
  without invoking an external compiler or writing artifacts.
- **Counted repeat loops in generated C:** support one-time count snapshots,
  zero-based indices, nested `repeat` and `while`, checked `RepeatNext`,
  negative-count E0019, and nearest-loop `break`/`continue` with
  interpreter-equivalent statement work budgeting.
- **Correctness and diagnostics:** checked integer operations, Boolean
  short-circuit logic, invalid-shift E0046, and explicit E0049 for unsupported
  backend forms. Storage retirement consumes no execution step.
- **Runtime and test hardening:** avoid zero-length C host callbacks, reject
  missing native C compilers in stable CI, and inspect freestanding x86-64 and
  AArch64 ELF object symbols on Linux.
- **Verified example:** `examples/native_scalar_repeat.srp` runs in the
  interpreter and is included in interpreter/C differential testing.

## Try the supported CLI

```sh
scarp version
scarp guide
scarp exec examples/native_scalar_repeat.srp
scarp verify examples/native_scalar_repeat.srp
scarp inspect modules --json examples/module_inspection.srp
scarp create hello-scarp
scarp inspect modules --json hello-scarp
scarp launch hello-scarp
```

The CLI remains interpreter-backed. `inspect modules` does not execute
normal program statements. The native C11 emitter is accessible only
to Rust embedding hosts, and its generated C requires a separate C11
compiler supplied by that host. See
[Proposal 0035](../proposals/0035-native-scalar-c11.md) for ABI, resource
limits, callbacks, supported operations and unsupported forms.

## Known limitations

- No `scarp compile` command, native `.srp` executable generation,
  package registry, network dependency resolver or stable ABI.
- The C11 backend rejects functions/recursion, floating-point and
  numerical collections, computed text, stderr/multi-argument output
  and unsupported intrinsics. The interpreter supports many of these;
  backend rejection is **not** a language removal.
- The experimental C ABI accepts work and print budgets only. General
  `ExecutionOptions` parity and automatic compiler/toolchain management
  are **not** available.
- Syntax, module formats, API semantics and error numbering may evolve
  before a stable language release. Existing published versions are immutable.

## Release gate (not yet fulfilled)

Before publication, merge the verified candidate to `main`, obtain passing
Rust checks on Ubuntu, macOS, Windows and Rust 1.74 **and** three native package
jobs on the exact final source commit, and inspect the generated archives'
`BUILD-INFO.txt`, source blobs, files and SHA-256 checksums. Independently
verify all seven uploaded assets before marking a GitHub Release as a

An explicit reviewed, version-and-full-commit-pinned authorization request

and publish. Do not reuse alpha.4's fulfilled authorization or modify its
