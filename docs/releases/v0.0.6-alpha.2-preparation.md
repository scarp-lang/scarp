## Candidate-source checklist

- [x] Release version in Cargo manifest, Cargo.lock and JSON metadata matches
  `0.0.6-alpha.2`.
- [x] Draft alpha.2 release notes and manifest-accurate compatibility scope
  are included **in source** for an eventual immutable tag.
- [x] Archive verifier explicitly retains inherited alpha.1 CLI/navigation/RMS
  requirements and adds alpha.2 cache contracts.
- [x] Native package smoke checks cover alpha.2 metadata and existing
  Scarp-project inspection/launch. Package signing is not claimed.
- [x] Release test fixtures cover missing cache documents, old metadata with
  valid archive hashes, immutable tag-source notes and tampered source bytes.
- [x] Compiler benchmark includes cold/warm token, AST and semantic-cache
  workloads with correctness assertions.
- [ ] Candidate PR checks: 7/7 on its exact head SHA.
- [ ] Candidate merged and **all 7 push checks green on the exact main SHA**.
- [ ] After verification, maintainer explicitly authorizes the exact
  approved source SHA and version in a **separate reviewed PR**.
- [ ] Authorization-control `main` revision passes its own seven checks.
- [ ] Guarded publisher verifies all native archives, source blobs,
  `BUILD-INFO.txt`, sidecars, `SHA256SUMS`, draft assets, and seven
  public downloads.
- [ ] Publish `prerelease=true`, `draft=false`, `make_latest=false`;
  verify the public tag points to the approved source and all digests.
- [ ] Add a post-publication validation record and remove the fulfilled
  `.github/release-request.json` in a separate maintenance PR.

The checkboxes above describe review milestones, **not** automatic
verification results. A successful PR check does not replace the
independent exact-commit push workflow gate.

## Explicit release hold

Do not add `.github/release-request.json` during candidate preparation.
The publisher requires a separately reviewed request with version, *full*
40-character `source_commit`, and the approved tagger name/email, after the
source main SHA is fixed and all seven required checks succeed.

Do not record a guessed SHA, checksum, action URL or release date.
The [release process](../releasing.md) describes exact-source approval and
draft recovery, and the [alpha.2 notes](v0.0.6-alpha.2.md) describe features
and compatibility.
