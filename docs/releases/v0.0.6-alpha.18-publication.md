# Scarp v0.0.6-alpha.18 — prerelease

## Changes

- Unify interpreter execution under `scarp exec`: with no source argument
  select the current directory's valid `scarp.project` or `Scarp.project`,
  otherwise `src/main.srp` then `main.srp`. Explicit source paths remain
  supported. `exec` supports bounded terminal prompts and typed input
  automatically; `run` remains explicitly opt-in for interactive prompts.
  A malformed project manifest is an error, never a fallback to arbitrary code.
- Begin **Scarp Lifetime** memory-retention hardening: zero-length finite and
  integer numerical windows now detach from their original backing buffers,
  while nonempty views still share immutable storage. Empty constructors use
  canonical shared storage. Existing source syntax and execution quotas do not
  change. Weak-reference Rust tests verify that original backing allocations
  are released when the last nonempty alias is dropped.
- Add pure `array_set(values, index, replacement)` for immutable fixed arrays.
  It returns a new `array<T, N>` snapshot without changing existing aliases.
  Bounds failures report E0063 at the index, and updates count against the
  cumulative array allocation limit (E0064).
- Interactive `ask()` retries interrupted prompt flushes within the existing
  execution budget, without reading input before a successful flush.
- Add byte-exact JSON inspection regression coverage for structured signatures,
  records, generated variants, Unicode prefixes, and CRLF source spans.

## Try the bundled example

```sh
scarp exec examples/array_updates.srp
scarp exec examples/lifetime_windows.srp
```

## Lifetime validation and measured trade-off

Before any publication, verify the exact merged source commit with passing
Rust CI on Linux, Windows and macOS, the minimum Rust 1.74 job, and the
package targets. Run `cargo test --locked --test lifetime_windows` and
`cargo test --locked --lib lifetime_storage_tests`. Run
`cargo bench --locked --bench lifetime -- --quick` for microbenchmarks.
The draft PR's comparison harness can benchmark identical source against the
original main commit. Short-run CI measured a roughly 1.5-2.3 ns cost for
empty-view construction and faster empty constructors; these are noisy
measurements, not verified overall speedups. The principal improvement is
lower retained buffer memory for empty views; no RSS measurements were made.

**Not yet a complete cycle collector.** Lifetime currently uses compiler-
planned scope cleanup and safe-Rust immutable reference-counted payloads.
Shared nonempty views, composites, and output captures can retain allocations.
Cumulative execution budgets are not live RSS limits. Closures, cycle handling,
concurrent tasks, FFI/native value transfers and AI tensor ownership need
separate reviewed designs. See [Lifetime](../memory-lifetimes.md).

## Compatibility and limits

- Before publication, a read-only CI release preflight downloads all three
  platform artifacts and independently validates exact source contents,
  archive inventory, checksums, version and source commit. It does not create
  a tag, GitHub Release, or publication request.

- Native ZIP/tar.gz archives now use canonical metadata; package CI performs
  an independent clean rebuild on each supported OS and requires matching
  SHA-256 for the complete archive and all file payloads. This verifies
  reproducibility on the same runner/toolchain, not across different systems.

- Native packages target Windows x64, Linux x64, and Apple Silicon macOS.
  The minimum supported source-build toolchain is Rust 1.74.
- Fixed-array updates and interactive prompt handling run in the interpreter.
  In-place indexed assignment is not supported. The ELF64 and C11 backends
  remain experimental and do not provide a general native compiler CLI.
- Package archives include per-target SHA-256 checksums and a combined
  `SHA256SUMS`.
