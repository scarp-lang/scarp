## Candidate integration gate

- [ ] Check that version 0.0.6-alpha.4 and tag are unused.
- [ ] Prepare a separate versioned candidate PR: update Cargo.toml,
  Cargo.lock, release metadata, README/version anchors, changelog and
  feature/compatibility matrix without rewriting historical release records.
- [ ] Add a public-facing, source-pinned alpha.4 release notes file without
  prepublication wording; add all new docs and examples to archive validation.
- [ ] Pass formatting, Clippy, debug/release tests, Rust 1.74, Linux, Windows,
  macOS, and three platform package tests on both candidate and final main.
- [ ] Download and inspect all native archives, README/docs/examples,
  exact-output fixtures, clean BUILD-INFO records, SHA-256 sidecars and
  the combined checksum manifest against the exact main source commit.
- [ ] Get separate maintainer approval naming the proposed version and full
  40-character source SHA, plus optional bounded publication time window.
- [ ] Only after approval, create and review the one-time release-request
  control PR; its new main commit must pass seven additional checks.
- [ ] Allow only the guarded publisher to tag and publish as a prerelease,
  then verify all seven public assets and write a postpublication record.
- [ ] Retire the one-time request without changing the published tag.

No release-request file, tag, generated checksum or publication claim
belongs in this preparation PR.
