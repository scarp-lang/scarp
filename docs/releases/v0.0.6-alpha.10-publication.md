# Scarp v0.0.6-alpha.10 — prerelease

## Interactive input

Use `scarp exec --interactive app.srp` to enable prompts using `input(prompt)`,
`ask(prompt)` or `ask_or(prompt, fallback)`. Use `input_integer`, `input_float`
and `input_bigint` to parse signed integers, finite floats and exact integers.
Prompts flush before reading. The `run` and `launch` commands accept the same
flag. Use `--input-file DATA.txt` for reproducible UTF-8 input.

`try_read_line()` distinguishes EOF from an empty input line with a Boolean
and a string. Invalid encoding, I/O failures and exhausted quotas produce
diagnostics. The existing fallback variants select a value at EOF.

`flush_stdout()` and `flush_stderr()` publish the selected stream during
interactive execution and replay after successful evaluation in ordinary
execution. Project tests can compare exact UTF-8 output using sibling
`.stdout` and `.stderr` fixtures. Both JSON reports omit stream contents.
Filesystem read, write and append functions are deferred.

## Fixed-size arrays and exact integers

Declare `array<integer, 2>` with `[array: 10, 20]`, or construct a typed empty
array with `[array: <integer>]`. Arrays are immutable and homogeneous. Arrays
support checked integer indexing, structural equality, nested values, and
typed functions and imports. Construction pays a cumulative allocation quota.

BigInt gains exact powers, GCD and LCM, integer square roots, bit lengths,
radix conversion from base 2 to 36, signed bitwise operations and shifts,
modular exponentiation, and a single-pass `bigint_divmod` returning
`tuple<bigint, bigint>`. All operations retain explicit resource limits.
Modular exponentiation uses variable-time arithmetic.

## Compiler and tooling

Rust hosts can opt into bounded compiler caches for scalar constants and editor
snapshots. Hosts can bind editor revisions to the bytes returned by their
source loader. An experimental exact Decimal foundation is available to Rust
hosts only. Scalar native verification reuses dataflow state across forward
edges. Scarp continues to execute source through the interpreter. The native
Rust API covers experimental scalar C11 and narrow ELF64 object emission.

## Compatibility and limits

- Module inspection emits schema 3 when a serialized type contains an array.
  Existing primitive and tuple inventories retain schemas 1 and 2. Diagnostic
  and navigation JSON use schema 1. The VS Code project-module browser needs
  schema 3 support for array-bearing inventories.
- Rust hosts should enable the `max_array_bytes` execution option and extend
  exhaustive matches on `ExpressionKind`, `SourceType`, `Value`, `Builtin`, and
  `DiagnosticKind`. Struct update syntax supplies the default array budget.
- Windows x64, Linux x64, and macOS Apple Silicon are the package targets.
  The compiler source supports Rust 1.74 and newer.
