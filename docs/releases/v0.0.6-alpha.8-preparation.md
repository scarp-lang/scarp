## Candidate behavior

```sh
scarp init hello
scarp project info --json hello
scarp verify hello
scarp run hello
scarp test --json --list hello
scarp test --json --require-tests --filter input examples/projects/calculator
```

From inside a project, `run`, `verify`, `project info`, and `test` accept
an omitted path. A missing or empty `tests/` directory reports zero tests.
`--require-tests` makes a zero selection exit 1 in run and list mode.
The 64-file discovery cap applies before filtering. Listing validates the
manifest and test paths without compiling sources or opening input fixtures.

Legacy `Scarp.project`, `create`, `launch`, and standalone `exec` remain
supported. Rename any existing `assert` identifier. Rust hosts with exhaustive
matches on `scarp::ast::Statement` and `scarp::diagnostics::DiagnosticKind`
must handle `Statement::Assert` and `DiagnosticKind::AssertionFailure`.
The module and CLI diagnostic JSON schemas retain their previous versions.
Project-info and test-report JSON each introduce their own schema version 1.

See the [manifest and migration guide](../project-v2.md), [CLI reference](../reference/cli.md),
[assertion contract](../assertions.md), and [test limits and fixtures](../project-testing.md).
The [calculator example](../../examples/projects/calculator/README.md) is
verified using the development CLI and the extracted platform packages.

## Separate development tracks

Immutable arrays ([#189](https://github.com/scarp-lang/scarp/pull/189)) and the
combined array, scalar, and cache stack ([#216](https://github.com/scarp-lang/scarp/pull/216))
need their own type-system, quota, and cache qualification. BigInt
([#200–#206](https://github.com/scarp-lang/scarp/pull/206)) needs independent
arithmetic and resource-budget qualification. E0062–E0064 remain reserved
for arrays. General native compilation, generic collections, dependency
resolution, registries, GPU/AI runtimes, formatting, and debugging are outside
this candidate. The manifest reserves an empty dependency block.

## Publication checklist

1. Review the aggregate draft, the compatibility changes, and the draft notes.
2. Verify the exact candidate and its current base with all seven CI jobs:
   stable Linux, Windows and macOS, Rust 1.74, and three native package jobs.
3. After integration approval, qualify the resulting exact `main` SHA again.
4. Verify the three native archives and checksum sidecars, their build records
   and source blobs, and the consolidated `SHA256SUMS`.
5. Obtain separate publication authorization naming the exact version and SHA.
   Use the existing [guarded publication procedure](../releasing.md) and verify
   the public annotated tag, prerelease status, and seven public downloads.
