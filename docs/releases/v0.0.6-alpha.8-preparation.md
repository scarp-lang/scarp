## Intended project CLI (requires final publication)

```sh
scarp init hello
scarp project info --json hello
scarp verify hello
scarp run hello
scarp test --list hello
scarp test --json hello
scarp test --json --require-tests hello
```

The existing `Scarp.project`, `scarp create`, `scarp launch`,
`scarp exec FILE.srp` and `scarp run FILE.srp` remain supported.
`scarp test` compiles and executes source, but `--list` is read-only.
Assertions are interpreter-backed statements; the experimental native C/ELF
backends do not claim support for this operation.

## Compatibility assessment

- `assert` becomes a reserved statement keyword. Existing code that used
  `assert` as an identifier needs a rename; this is a source compatibility
  consideration for this experimental language.
- The lower-case `scarp.project` v2 manifest is a distinct, optional format.
  The upper-case legacy v1 format remains supported; avoid committing both on
  case-sensitive systems because v2 has precedence.
- `--require-tests` is strictly opt-in. The default empty-suite exit status
  remains success for compatibility; strict mode returns 1.
- `--json` test results are schema version 1. Source-output capture is
  separate from structured result output, but a compiler/runtime diagnostic
  may include a relevant excerpt of the source line.
- Assertion failure uses `E0065`; `E0062`–`E0064` are reserved for the
  separate immutable-array work. Do not reuse those codes.
- The test runner is bounded to 64 direct `.srp` files; no recursive scanning,
  arbitrary runtime timeouts, packages, network dependencies, or test-specific
  input prompts are introduced.

## Explicit exclusions

Immutable arrays (#189), BigInt (#200–#206), native compiler generalization
(#214 and issues #128/#132), compiler caching (#212–#213), and combined
numeric/array/cache integration (#216) are separate, unmerged work.
No tensors, automatic differentiation, GPU execution, general package manager
or native `scarp compile` CLI is claimed by this milestone.
