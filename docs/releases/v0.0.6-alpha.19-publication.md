# Scarp v0.0.6-alpha.19 — prerelease

## Changes

- Add the Rust semantic API `TypeRegistry::accepts_callable` for named function signature compatibility. Parameters and return types remain invariant, and pure implementations may satisfy an impure callable requirement, never the reverse.
- Add checked Rust embedding handles for named Scarp functions, including snapshot-bound invocation, positional and named host argument mapping, omitted default parameters, and dynamically rebindable slots constrained by signature and effects.
- Add export-aware callable handles for linked modules. Private declarations stay inaccessible to export-only selection, and diagnostics retain source mappings.
- Introduce deterministic `ExecutionUsage` receipts for embedded callable execution, including returned failures and read attempts. A `HostInvocationLedger` enforces per-host cumulative steps, calls, output/capture, payload allocation, and input limits across repeated invocations.
- Validate pre-existing Rust host argument counts, string payload UTF-8 bytes and named labels before invoking the interpreter. Admitted argument charges remain visible even when later callable binding fails.
- Use unwind-safe receipt debiting for work completed before a caller-provided output writer panics during replay, preventing that completed Scarp execution from escaping the host's cumulative ledger.

## Rust host example

```sh
cargo run --locked --example host_callable_invocation
scarp exec examples/callable_effect_boundaries.srp
```

## Compatibility and limits

This is an **experimental Rust embedding foundation**, not first-class source-level function values. Scarp source still cannot pass named functions as values, construct closures, capture lexical environments in functions, or indirectly call arbitrary values. Ordinary named `funcra` syntax and published Alpha.18 binaries are unchanged.

Cumulative quotas count deterministic interpreter events, not wall time or process RSS. Host argument byte accounting covers string payloads and argument labels, not all nested composite storage. Output that a host writer already accepted cannot be undone. The unwind guarantee applies to completed interpreter receipts replayed through output writers; it does not cover arbitrary panicking input readers during evaluation, `panic=abort`, process crashes or unsafe host application code.

The release package targets Windows x64, Linux x64, and Apple Silicon macOS. Exact-source CI must pass Rust 1.74 compatibility, debug and release tests, formatting, strict Clippy and rustdoc, cross-platform builds, reproducible archives and the closed release archive inventory before publication.
