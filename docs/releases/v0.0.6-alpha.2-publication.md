# Scarp v0.0.6-alpha.2 — prerelease

Scarp is an experimental programming language with an interpreter-backed CLI,
a typed compiler front end, source modules and numerical primitives. This
prerelease focuses on **optional, bounded compiler caching and safer compiler
internals**, rather than new source-language syntax or a general native
executable compiler.

## New in v0.0.6-alpha.2

- **Dependency-aware module invalidation planning:** An opt-in Rust API
  captures trusted loader identities, resolved imports and transitive
  importers. It compares independently compiled graphs and identifies
  affected sources conservatively, without accepting an unchanged graph as
  proof of cache safety. Edit-list quotas are validated completely before
  an unknown-path fallback. See
  [issue #117](https://github.com/scarp-lang/scarp/issues/117)
  and [PRs #121](https://github.com/scarp-lang/scarp/pull/121),
  [#127](https://github.com/scarp-lang/scarp/pull/127).
- **Caller-owned semantic compilation cache:** Reuses successful
  whole-graph resolution only when the loader has discovered the current
  graph and source bytes, resolved imports, display labels, compiler limits
  and caller-provided revisions match exactly. Errors are never replaced
  with stale cached results.
  [PR #122](https://github.com/scarp-lang/scarp/pull/122).
- **Per-source lexical token cache:** Retains successful lexing under
  independent file, byte, identity and token quotas. A cache hit returns
  source-relative spans that the compiler repositions to the new source
  map. Parsing and semantic checks still run.
  [PR #123](https://github.com/scarp-lang/scarp/pull/123).
- **Per-source parsed syntax cache:** Reuses successful ASTs with nested
  spans correctly rebased for a fresh source map. Import validation,
  cycle/depth checks, type checking, constant evaluation and compiler
  resource limits still apply.
  [PR #124](https://github.com/scarp-lang/scarp/pull/124).
- **Source-scoped cache eviction:** A new opt-in Rust API can discard
  cached tokens, parsed trees and whole-graph semantic results associated
  with a trusted source identity, leaving unrelated caches intact.
  Eviction does not wipe memory or revoke previously returned programs.
  [Development contract](../development/cache-eviction.md).
- **Native backend maintenance:** The existing experimental scalar C11
  Rust API now shares a dedicated internal acceptance/resource preflight.
  The source language, supported C11 subset and public CLI are unchanged.
  [PR #130](https://github.com/scarp-lang/scarp/pull/130).
- **Release and design documentation:** Corrected historical release
  version labels and added reviewed next-step requirements for a private,
  verified scalar IR and future freestanding ELF object writer.
  **Those future native features are not implemented by this release.**
  [PR #131](https://github.com/scarp-lang/scarp/pull/131).

## Install and run

Choose the native archive for your platform in this release's assets:

| Platform | Archive target |
| --- | --- |
| Windows x64 | `x86_64-pc-windows-msvc` (`.zip`) |
| Linux x64 | `x86_64-unknown-linux-gnu` (`.tar.gz`) |
| macOS Apple Silicon | `aarch64-apple-darwin` (`.tar.gz`) |

Each platform archive has its own `.sha256` sidecar. The combined
`SHA256SUMS` manifest covers the three archives. Compare the downloaded
archive against the published checksum before extracting or running it.

The archives contain the Scarp CLI, examples and documentation. For instance,
after extraction, use `scarp version`, `scarp guide`,
`scarp exec examples/hello.srp`, or
`scarp verify examples/hello.srp` (using the appropriate executable path
on your platform).

The four new caches are **Rust embedding APIs**, used from a compatible
Cargo source checkout. The release archives do not include a separate
precompiled Rust library.

## Compatibility and limits

- Scarp remains experimental, interpreter-backed and not a stable language
  or ABI. Existing Scarp-first CLI commands, project mode, typed functions,
  source navigation and numerical features remain available.
- The release does **not** add a language server, file watcher, package
  registry, general native compilation, `scarp compile` command, object
  file generator, fixed-size source arrays or GPU execution.
- Cache retention limits are **logical payload quotas**, not verified
  process-heap caps. Exact cache hits still require loader work and current
  validation. No cross-platform speedup is guaranteed.
- The opt-in C11 scalar emitter remains limited to supported integer/Boolean
  programs. A separately chosen C11 compiler is needed to turn its output
  into machine code; this does not make it a general Scarp native compiler.
