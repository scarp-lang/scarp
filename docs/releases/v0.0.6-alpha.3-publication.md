# Scarp v0.0.6-alpha.3 — prerelease

Scarp is an experimental, interpreter-backed programming language with
typed source modules and bounded numerical operations. This prerelease
adds deterministic score-ranking and temperature-controlled probability
functions, alongside correctness and verification work inside the
experimental scalar compiler pipeline.

## New in v0.0.6-alpha.3

- **Top-K candidate ranking:** `topk(scores, count)` returns original
  zero-based indices of the highest finite scores, greatest first.
  `topk_values(scores, count)` returns those original values in identical
  order. Equal scores select earlier indices first, even for signed zeros;
  zero results are allowed. Both use a bounded heap with explicit work and
  allocation quotas.
- **Temperature-aware probabilities:** `softmax_temp(scores, temperature)`
  and `logsoftmax_temp(scores, temperature)` return finite vector results.
  The temperature must be a positive float. Maximum shifting and
  compensated normalization protect against avoidable overflow; genuinely
  unrepresentable log probabilities produce a diagnostic.
- **Compiler-owned scalar IR:** Internal, typed expression and statement IR
  represents branches, loops, stores, and output for the existing restricted
  scalar C11 backend. The verifier checks types, branch targets and
  must-initialize storage on all reachable paths.
- **Differential validation:** Test-only scalar IR execution compares
  outputs, execution budgets and diagnostics with the ordinary interpreter.
  This is a correctness milestone, not a public native code generator.

## Start using the new functions

```scarp
bind scores = [1.0, 5.0, 5.0, -2.0, 3.0];
print(topk(scores, 3));                // [integer: 1, 2, 4]
print(topk_values(scores, 3));         // [5.0, 5.0, 3.0]
print(topk(softmax_temp(scores, 0.5), 2)); // [integer: 1, 2]
```

See the included `examples/topk_scores.srp` and
`examples/temperature_softmax.srp`, each with an exact-output fixture:
`examples/topk_scores.stdout` and `examples/temperature_softmax.stdout`.
Documentation and contracts are bundled as `docs/topk-selection.md` and
`docs/temperature-softmax.md`. Version-specific source is available via
[Scarp GitHub](https://github.com/scarp-lang/scarp).

## Compatibility and limits

New built-ins are pure and typed; `topk` returns `integers`,
`topk_values` returns `vector`, and both temperature functions return
`vector`. They do not mutate input vectors, change source syntax, or add CLI
commands. Rust library consumers with exhaustive matches over
`numeric::Builtin` must handle the new enum variants.

The interpreter remains the execution engine. The C11 source emitter is
still restricted to its documented scalar subset, accessible through the
experimental Rust embedding API; it is **not** a general native object writer.
This release does not provide an LSP, GPU backend, tensor engine, AI agent
framework, random sampling, top-p decoding, stable ABI, or package manager.

The supported native archives are for **Windows x64**, **Linux x64**, and
**macOS Apple Silicon**. They include the interpreter-backed Scarp executable,
source examples and documentation. No crate or npm registry publication is
implied. This is an experimental prerelease, not a stable language release.

The exact source SHA and verified asset digests are recorded separately in
the guarded publisher's verification logs and post-publication record. The
release publisher reads these notes from the immutable approved source commit,
never from a moving checkout.
