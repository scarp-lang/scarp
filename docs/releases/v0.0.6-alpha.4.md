# Scarp v0.0.6-alpha.4 — proposed release notes

**Versioned source candidate only: not a tag or published prerelease.**
The latest published prerelease is [v0.0.6-alpha.3](https://github.com/scarp-lang/scarp/releases/tag/v0.0.6-alpha.3).
This development source declares 0.0.6-alpha.4. These notes do not authorize publication.

## Proposed contents

- [PR #153](https://github.com/scarp-lang/scarp/pull/153) and [PR #155](https://github.com/scarp-lang/scarp/pull/155): sampled calculus, cumulative trapezoidal integration and interval slopes. Already merged but not included in published alpha.3.
- [PR #157](https://github.com/scarp-lang/scarp/pull/157): merged bounded cosine similarity, deterministic scaled numerical reduction and explicit zero-vector/shape errors. Verified merge commit bd34ebfdb3ba64497146c766944cb411532758ae. Not included in published alpha.3.
- [PR #158](https://github.com/scarp-lang/scarp/pull/158): merged as ffccc763ef95606ff23d47b7c0c4c466d94e57c6, after four Rust and three package checks passed. It provides a limited safe-Rust x86-64 ELF64 relocatable integer-kernel writer, with an independent host-link test. This remains experimental and unreleased; no general compiler CLI, stable runtime ABI or executable linking.
- [Draft PR #149](https://github.com/scarp-lang/scarp/pull/149): Top-P selection remains divergent from main. Exclude until it is independently reconciled, verified, made review-ready and merged.

## Explicit exclusions

No native executable compilation, generalized x86-64 runtime, GPU backend,
tensor engine, autodifferentiation, stable language ABI, LSP, new keywords,
fixed-size arrays or package registry is implied by this version. Existing
interpreter-backed CLI semantics stay unchanged.

## Prerelease requirements

A separate candidate integration PR must align Cargo.toml, Cargo.lock,
release metadata, changelog, release documentation, compatibility notes,
offline tests and package verification. The final merged main SHA must pass
four Rust jobs and three native-package jobs, with inspected archives,
source identities, clean build records and SHA-256 sidecars. The maintainer
must separately approve the exact version and full 40-character source SHA.
Only after that approval should a distinct reviewed one-time release
control PR enable the guarded publisher. Preparation is not authorization.

See [alpha.4 checklist](v0.0.6-alpha.4-preparation.md) and
[release engineering](../releasing.md).
