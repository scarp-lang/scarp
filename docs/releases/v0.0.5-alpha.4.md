# Scarp v0.0.5-alpha.4 — prerelease

Scarp is an experimental, interpreter-backed programming language written in Rust. This prerelease extends the 0.0.5-alpha.3 compiler with an explicit, offline project workflow and safer project-level static verification.

## New in alpha.4

- **`scarp create DIRECTORY`** generates a fresh, runnable project containing `Scarp.project` and `src/main.srp`. It never adopts or overwrites an existing destination, even if that directory is empty.
- **`scarp launch DIRECTORY`** validates a bounded, versioned manifest, resolves the declared entrypoint inside the selected project, and executes it through the real Scarp interpreter. Existing execution budgets and diagnostics apply.
- **`scarp verify DIRECTORY`** uses the same manifest and path protections to check the project's entrypoint and imported modules statically, without running ordinary program statements. `scarp verify FILE.srp` remains available.
- The new project workflow has cross-platform integration tests for Unicode project names, alternate entrypoints, invalid/oversized manifests, path traversal, symlink escapes, runtime-only failures and schema-v1 JSON diagnostics.
- Improved documentation about the published CLI capabilities, supported bitwise/radix operators and the difference between runtime execution and static verification.

## Get started

```sh
scarp version
scarp create hello-world
scarp verify hello-world
scarp launch hello-world
```

The `Scarp.project` file is deliberately small:

```text
scarp-project: 1
name: hello-world
entry: src/main.srp
```

`launch` and project-directory `verify` require an explicit project path; they do not search ancestor directories. `verify` does not execute normal runtime statements or accept execution-budget flags.

## Compatibility and limits

This is an **alpha prerelease**, not a stable language/runtime contract. Source syntax, manifest format and embedding APIs may change. The older `run`, `check`, `tokens` and `modules` CLI routes remain available temporarily during migration; historical `check` is not equivalent to static-only `verify`.

**Not implemented:** native `.srp` executable generation, a Scarp package registry or dependency lockfile, general-purpose user-defined records/enums, a general tensor/autograd engine, a GPU backend, and async/concurrency in the language. `cargo build` builds the Rust-based Scarp interpreter, not a native executable from Scarp source.

`Scarp.project` is a development manifest v1, not a published stable workspace/package standard. Project filenames and manifest entries are validated before any execution. The new CLI does not download dependencies or send source code to a remote service.

## Platforms and verification

The release workflow prepares and smoke-tests native archives for Windows x64, Linux x64 and macOS Apple Silicon. Each archive is accompanied by a SHA-256 checksum, and a combined `SHA256SUMS` is required before publication. The final release must pass all four Rust check jobs and all three native package jobs against the **exact source commit**, then pass the publisher's build-record, source-blob, draft-asset and public-download verification.
