Development candidate, 10 November 2026. The latest verified public binary at
preparation time is alpha.5. Publication gates remain mandatory; this document
does not itself create a release or grant authorization.

Integration preserves the selected PR heads as commit ancestors. The combined
tree adapts input resolution to structural `SourceType`, merges CLI budgets and
diagnostics, and adds `core_foundations_integration` plus the executable
`examples/core_input_tuple.srp` with raw CRLF input. This program parses an
integer, trims/replaces Unicode text, returns a tuple from an imported impure
function and passes it to a pure formatting function. Independent input, text
and tuple quotas and failed imported conversion must preserve atomic output.

BigInt #172, order statistics #171, tutorial migration #173, superseded Top-P
#149 and old implementation stacks are excluded. Existing implemented loops,
functions, numerical kernels and native experiments are preserved.

## Compatibility and limitations

See [tuple migration](../tuples.md), [input contract](../program-input.md),
[text contract](../text-foundations.md) and [CLI reference](../reference/cli.md).
Source-facing annotations/signatures and `Value::kind()` use `SourceType`;
complete `ExecutionOptions` struct literals add `max_tuple_bytes`. Primitive IDs
remain unchanged. Tuple-exposing module inventories use JSON schema 2;
primitive inventories, symbols/references and diagnostics retain schema 1.

Default tuple payload quota is 8 MiB. Tuple arity is 1–32, depth at most 32 and
shape at most 4096 nodes. Input defaults are 64 KiB raw bytes per line, 1 MiB
cumulative and 4096 reads. CR/LF count. Input is explicit and non-rollbackable;
program output is buffered until successful evaluation. Selected terminal reads
and evaluating `check` report E0054; `verify` and inspection never read input.

Empty tuples, tuple module constants, dynamic tuple indices, destructuring,
mutable elements, interactive prompts, general arrays/maps, optional/results,
GPU/tensor runtimes and native tuple/input execution remain unsupported. This
is an experimental prerelease, with no stable language or Rust API guarantee.

## Publication gates

1. Formatting, warnings-denied Clippy, locked all-target/debug/release tests,
   documentation/example/oracle checks and minimum Rust 1.74 qualification.
2. All four Rust and three package jobs on the exact combined PR, then the
   exact merged main source. Earlier individual PR jobs do not replace these.
3. Verify three clean native archives against the exact source Git blobs,
   BUILD-INFO, extracted program behavior and all SHA-256 checksums.
4. Use a fresh one-time release request pinned to the final verified source,
   preserving branch protections and all existing release tags/assets.
5. The guarded publisher rechecks both source and control main matrices,
   creates an annotated tag and draft prerelease, compares all seven uploaded
   assets, publishes with latest=false and verifies public downloads.
6. Record publication evidence separately, then retire the fulfilled request.

Supported native archives: Windows x64 MSVC, Linux x64 GNU and macOS Apple
Silicon. No package-registry publication or stable release is part of this work.
