# Scarp Alpha.20 engineering preparation

Protected main at the start of qualification was
`b7c555013a358e1b4f23d52d74392fadc09f63be` with tree
`619d9bab0e540f1d973d5c353190471af3734796`. The published baseline is
[Alpha.19](v0.0.6-alpha.19-validation.md), verified independently of main.

## Candidate scope

- Lower one pure, parameterized Scarp function through the existing lexer,
  parser, resolver and scalar IR. Independently verify argument slots, local
  initialization, typed returns, forward branches and absence of fallthrough.
- Emit x86-64 System V code with a checked stack layout, lexical retirement
  enforced by the verifier, and one shared stack-restoring return path.
- Cache logical UTF-8 byte totals on immutable composite payloads so host
  admission can count nested string occurrences with bounded work.
- Preserve persistent tuple replacement, lexicographic numeric tuple ordering,
  exact decimal literals, and legacy project manifest reading.
- Verify binary archives against a closed inventory at the candidate source SHA.
  The fulfilled Alpha.19 publication request is removed from this candidate.

## Qualification

Use the exact candidate SHA in the Rust checks and Release packages workflows.
Both must pass on the candidate and again on protected main after integration.
Validate Rust 1.74, strict Clippy and rustdoc, debug and release tests, and
byte-identical Windows x64, Linux x64 and macOS arm64 rebuilds. Confirm all
three archives record the intended SHA and verify their checksums together.
See [the release process](../releasing.md) for the separate publication decision.

## Scope still under development

Native loops, heap-backed types, public fixed-width types, indirect source
calls and closures require further design. Current Lifetime retirement tracks
lexical ownership and supports shared immutable values. Live heap accounting
and a complete native resource-transfer model remain future work.
