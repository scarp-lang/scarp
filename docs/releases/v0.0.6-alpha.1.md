# Scarp v0.0.6-alpha.1

Status: **unpublished prerelease candidate** for the first v0.0.6 alpha.
This note describes reviewed source behavior, not evidence of publication.
The latest published prerelease remains v0.0.5-alpha.5. No stable v0.0.6,
package-registry publication or external documentation deployment is implied.

## Cross-file source intelligence

- Opt-in `modules::symbols` snapshots retain original declarations and uses
  before linker rewriting and constant folding. Functions, parameters, constants,
  local bindings, import aliases, loop indices, contract results and builtins
  have compilation-local identities; lexical shadowing and public/private rules
  follow the authoritative module resolver.
- `compile_indexed_with_loader` / `compile_indexed_file` and indexed graph
  resolution expose go-to-definition and find-references without executing
  statements. Imported calls, namespace tokens, writes and named-argument labels
  keep original file-local UTF-8 spans and one-based Unicode-scalar positions.
- `inspect symbols` and `inspect references` accept a file or explicit project
  directory. Text and deterministic JSON schema-v1 outputs are additive; the
  existing module and diagnostic JSON contracts remain unchanged.
- Index limits separately bound symbols, references, retained name bytes and
  logical indexing work. E0050 reports index exhaustion; ordinary compiler
  validation errors retain precedence. Invalid/cyclic/private imports expose
  no partial snapshot. Ordinary compilation does not retain an index.

See [the API/schema contract](../symbol-index.md), exact JSON fixtures and the
self-checking Rust [embedding example](../../examples/symbol_index.rs).

## Numerical and native validation work

- Pure `rms(vector) -> float` uses a scaled compensated sum of squares and
  restores scale after normalization. Finite nonempty inputs remain finite even
  when their norm or squared sum would overflow. Empty input reports E0034 at
  its argument; all-zero input returns +0.0. Windows read only visible elements.
- RMS prepays 4n native work steps and allocates no new numerical payload;
  input creation retains its normal quota. Tests cover maximum finite values,
  subnormals, strict typing, defaults/contracts/modules, exact diagnostics and
  atomic streams, with an independent high-precision Decimal oracle.
- Linux CI requires both GCC differential checks and Clang UBSan checks, in
  addition to freestanding ELF validation. A portable `PRIuMAX` host fixture
  fixes Windows GCC's size formatting without relaxing `-Werror`.

See [RMS semantics](../root-mean-square.md). No C11 language subset extension is
claimed: it remains an experimental integer/Boolean Rust-hosted source emitter.

## Try the candidate source

```sh
cargo build --locked --offline
target/debug/scarp inspect symbols --json examples/symbol_navigation.srp
target/debug/scarp inspect references --json examples/symbol_navigation.srp
target/debug/scarp exec examples/symbol_navigation.srp
target/debug/scarp exec examples/root_mean_square.srp
cargo run --locked --offline --example symbol_index
python scripts/test_symbol_index_json.py target/debug/scarp
python scripts/test_rms.py target/debug/scarp
```

On Windows, use `target/debug/scarp.exe`. The navigation example prints `30`;
the RMS example has an exact `.stdout` companion. Static commands do not run
runtime statements, arithmetic domains or contracts; compile-time scalar
constant validation still occurs. Legacy `check` continues evaluating selected
paths, with its existing resource and atomic-output behavior.

## Compatibility and exclusions

Existing valid programs retain their syntax, primitive types and runtime APIs.
User functions named `rms` retain precedence. Public `numeric::Builtin` gains
`Rms`, and `DiagnosticKind` gains `SymbolIndexLimit`; exhaustive Rust host matches
need new arms. Navigation types and compile entry points are additive. Index IDs
belong to one snapshot and must not be persisted across edits or mixed between
compilations. JSON consumers must check `schema_version` and `kind`.

This candidate has no LSP server, rename operation, incremental cache, incomplete-
source recovery or cross-edit stable symbol identity. Primitive type keywords
and operators are not value-reference sites. Builtins/implicit contract result
symbols have no source definition. General arrays and tensors are deferred in
[proposal 0036](../proposals/0036-composite-values-and-tensor-boundaries.md).
No automatic differentiation, GPU runtime, native executable CLI, general C11
function/vector support, package registry or stable ABI is introduced.

Scarp Docs, Scarp by Example, Playground and VS Code consumers have not been
changed or deployment-tested by this work. Their maintainers can consume the
new opt-in API/schema after version checking; no external integration is claimed.

## Platforms and publication integrity

The intended native archive matrix remains Windows x64 MSVC, Linux x64 GNU and
macOS Apple Silicon. Rust 2021, minimum Rust 1.74, `unsafe_code = "forbid"`, no
third-party dependencies and `publish = false` are preserved. Platform CI must
verify this exact candidate before approval; a prior PR's success is insufficient.

Each native job extracts its archive and runs the executable, example corpus,
project workflow, navigation JSON and RMS quota/domain probes. The release
verifier requires new and inherited files, exact source Git blobs, clean
BUILD-INFO records and archive hashes. A release would contain three native
archives, three `.sha256` sidecars and `SHA256SUMS`: seven uploaded assets.

The separate process in [releasing](../releasing.md) requires fresh approval for
this exact version and full final-main source SHA after all four Rust and three
package jobs and archive verification pass. This preparation creates no release
request, tag or draft. Historical tags/assets remain unchanged. Checksums detect
corruption; they are not signatures or reproducible-build attestations.
