# v0.0.6-alpha.1 engineering audit

Audit date: 5 November 2026. This is candidate-development evidence, not a
publication record. Exact final-main CI and archive verification must follow
the preparation PR before a separate exact-version/source-SHA approval.

## Verified baseline and risks

The checkout was fast-forwarded from old alpha.3 maintenance to current main
`1aff6cabf93f2e0bce6953b29e1abe7d00ebd5fb` before development. Cargo and the live
release list agreed on published v0.0.5-alpha.5; its source was
`2eeed0aa52ccb59523307841ad8ffbd83f8911a8`. Baseline Rust run
[41827237677](https://github.com/scarp-lang/scarp/actions/runs/41827237677) and
package run [41827237698](https://github.com/scarp-lang/scarp/actions/runs/41827237698)
passed. The v0.0.6 tag line was unused when selected and rechecked during
preparation. No previous authorization is reused.

The audit traced lexer/parser/flat AST, typed resolver and type registry,
constant evaluator, linker/trusted loaders, execution/lifetime plans, bounded
interpreter, diagnostic JSON, project manifest handling, C11 emitter and release
tooling. Main already contained primitive annotations, scalar constants,
interpreter-backed projects, project module inventory and the restricted C11
Rust embedding API. There were no open issues. Historical PRs #16–#27 contain
stacked or superseded implementations; none was merged wholesale. Development
branch `05b4c40f63567267f5d9662ba8108d403d682f88` was not imported.

The highest-value gap was original source identity after module linking:
constant substitution and function-name rewriting discarded reference sites.
Capturing metadata before those transformations avoids a second resolver or
parser. Other risks were index growth, byte/column confusion, partial metadata
on semantic failure, platform-dependent C test hosts and overstated type/value
support from tooling-only composite descriptors.

## Completed scope and verification

[PR #108](https://github.com/scarp-lang/scarp/pull/108) adds the bounded opt-in
symbol/reference API, static CLI, schema-v1 fixtures and 25 Rust tests. Its
seven CI jobs passed in Rust run
[42011182172](https://github.com/scarp-lang/scarp/actions/runs/42011182172) and
package run [42011182106](https://github.com/scarp-lang/scarp/actions/runs/42011182106).
Local debug validation passed 717 tests, strict all-target Clippy, 25 focused
Rust 1.74 tests and eight independent JSON/location checks. Tests include
shadowing, forward/recursive functions, import privacy/cycles, constants,
defaults/contracts, named labels, writes, Unicode/CRLF/BOM, graph failures,
exact budgets, deterministic queries and writer failures.

[PR #109](https://github.com/scarp-lang/scarp/pull/109) corrects a C host fixture's
nonportable `%zu` formatting with `PRIuMAX`. Explicit local required-Clang and
required-GCC runs each passed five tests. It also requires Linux GCC and Clang
UBSan differential checks alongside the existing freestanding ELF validation;
all seven PR jobs passed. This changes validation coverage, not the supported
native language subset or generated-code semantics.

[PR #110](https://github.com/scarp-lang/scarp/pull/110) completes RMS with nine
Rust tests, exact-output examples, three independent Python checks and native
executable probes. The 200-digit Decimal oracle covers 37 extreme/generated
vectors; a separate maximum-length check verifies the exact input payload quota.
Rust 1.74, strict Clippy and the correctness-checked numerical benchmark passed
locally. All seven PR jobs passed in Rust run
[42014420756](https://github.com/scarp-lang/scarp/actions/runs/42014420756) and
package run [42014420568](https://github.com/scarp-lang/scarp/actions/runs/42014420568).

Candidate preparation updates Cargo/lockfile, current-versus-published anchors,
notes and package rules. Damage tests require new navigation/RMS files and
inherited features, reject stale metadata despite valid archive checksums and
compare tagged notes/JSON against exact source blobs. Existing historical
release tests remain enabled. The release request is absent; no candidate tag,
draft, release or registry publication is created.

Final local debug/release, docs, full scripts, exact-main matrix and downloaded
archive results belong in the final engineering report after the candidate is
merged. PR checks alone are not final-source release evidence. Native Linux,
macOS, UBSan and ELF execution rely on their actual CI hosts; Windows local
validation cannot establish those platform results.

## Compatibility and deliberate deferrals

Navigation is opt-in; ordinary compilation retains no index. Existing module
and diagnostic schemas, valid syntax, values and execution budgets remain
compatible. `Builtin::Rms` and `DiagnosticKind::SymbolIndexLimit` require new
arms in exhaustive Rust matches. IDs are snapshot-local; there is no promise of
LSP/rename, cross-edit IDs, incremental caching or incomplete-source recovery.
No source code or constant payload is added to navigation JSON.

Arrays and generalized tensors are deferred in
[proposal 0036](../proposals/0036-composite-values-and-tensor-boundaries.md).
The completed smaller feature is RMS. No placeholder array parser/runtime,
automatic differentiation, GPU execution, general native CLI or ABI is shipped.
External Docs/By Example/Playground/VS Code repositories were not modified;
consumers need explicit version/schema checks and their own integration tests.

No performance optimization is claimed. The compiler benchmark adds an opt-in
indexing case on the existing four-file graph, checks every reference's query,
and keeps normal compilation separate. Raw repeated measurements, host/toolchain
and variance should accompany any later performance assessment; logical index
or numerical allocation counters are not process-memory measurements.
