# Alpha.19: executable host named-callable entry

**Status: draft, Rust embedding API only.** Published alpha.18 and the
source-level named-call language remain unchanged. This engineering slice
builds on the immutable callable type and identity work of PRs #337–#340.

## New, executable embedding contract

A Rust embedder compiles a ResolvedProgram, constructs a CallableCatalog,
binds a checked named function declaration, and invokes it with an owned
Vec<Value> using NamedCallableRef::invoke_with_io_and_options. The result
is the function's owned Value, not the file-entry output. An alternative
invoke_with_input_and_options accepts explicit BufRead and InputLimits.

The host target is bound by program allocation, exact declaration index and
same-arena canonical TypeId. It retains Arc<ResolvedProgram> and survives a
caller dropping its original catalog/program reference. A declaration index
is an inspection capability, not a public-module visibility or access grant.

## Same interpreter machinery, no second evaluator

The existing machine now supports a host function Frame as its initial frame.
It still runs the same evaluation loop, defaults, needs and ensures contracts,
body statements, recursion/tail-self transfer, work budgets, call traces and
buffered output events. An initial host call counts as a function call and
charges the normal frame work/live slots and one call depth. A virtual file
frame corrects nested-call depth comparisons, but consumes no file slots.
A host call does not execute entry-script statements.

Outputs remain transactionally buffered and only replay to stdout/stderr after
successful evaluation; writer failures remain host IO errors. An explicit
input reader permits existing read_line semantics; reader consumption cannot
be rolled back. Externally constructed host argument payloads are not newly
allocated by the interpreter and are not charged as new payload allocations.

## Narrow checked positional parameters

Currently, supplied arguments must be values of integer, boolean, finite
float or string types, matching the exact declared parameter type. Host text
must be at most MAX_TEXT_BYTES UTF-8 bytes. Excess/missing positionals,
mismatches, unsupported composites and oversized strings fail before any user
code runs. Trailing omitted defaults are evaluated by the usual interpreter
and may themselves be more complex. This is a deliberate restriction until
nominal runtime-value provenance, broader payload limits and module visibility
have been reviewed for exported host-call APIs.

Returns can be any Value generated by valid Scarp code. There is no host
named-argument adapter, no implicit coercion, and no implicit pure context.

## Not implemented

This is **not** Scarp-language first-class functions. Scarp source cannot
store, pass, capture, return or indirectly call function values. No closures,
mutable captures, new GC, native callable ABI, direct CLI command or source
syntax were introduced. Do not market first-class functions or publish a
release until those features and their test gates actually exist.

Regression tests check direct/host behavior, contracts/defaults, output
rollback, type/arity checks, text bounds, module imports, retained snapshots,
reader input, resource quotas, terminal recursion and writer errors.

Only draft PRs are authorized for this milestone; no main merge or tag.
